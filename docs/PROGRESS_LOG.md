## Step 67 (Gazette M) — pack paths: `resolvePackPath`, `sliceFacts`, `pathIndex`
**Date:** 2026-11-11  **Status:** done
**Built:** in `src/lib/gazette.ts`, a "Pack paths" section: `resolvePackPath(facts, path)` for dotted and indexed paths (`games[2].margin`, `rosters[0].carriedBy[0].price`, `belt`), `unresolvedPaths()`, `sliceFacts(facts, paths)` and `pathIndex(facts)` (every citable row with a one-line label). `src/lib/gazette-paths.test.ts`, 15 tests against the committed 2025 week 10 pack. Section M added to `docs/PROJECT_PLAN.md` §13; `docs/GAZETTE_ROADMAP.md` is the build plan. Suite 851.
**Decisions:** (1) **A slice widens every path to its row**: `games[2].margin` brings all of `games[2]`, because a margin without the two names it belongs to is a figure a Writer can only misattribute. (2) **Arrays keep their indices** in a slice, uncited rows null, so `rosters[3]` in a plan is still `rosters[3]` in the slice the Writer reads. A compacted array would have silently re-pointed every citation. (3) The continuity fields (`priorThreads`, `priorColumns`, `priorHeadlines`, `priorLenses`, `reservedGenres`, `kind`) are not addressable and never sliced: each stage is handed the notebook explicitly. `notes` is always in a slice, because it carries caveats like "only six teams played". (4) A path to a null field resolves to null, the same as a missing one: a storyline cannot be evidenced by an absence. (5) The index lists rows, not leaves; leaf paths still resolve. A section with no labeller (the player stat lines, when they arrive) is indexed by a generic fallback, so it is citable the day it exists.
**Learned:** (1) "A slice of all paths deep-equals the pack" is only true of the pack's *content*: empty sections (`recordBook: []`) have no rows to cite, so they never appear in a slice. The test defines content explicitly rather than weakening the check. (2) A slice is a strict subset of the pack, so grounding prose against a slice would be *stricter* than the gate, and would fail a true sentence that quotes a figure the plan happened not to cite. A test pins that the gate reads the full pack. (3) Every label is built from pack strings and numbers, so a Story Desk that copies one verbatim cannot trip `ungroundedNumbers`; tested, because the labels go into a prompt. (4) The plan already has three features numbered from 63 and one from 67; the convention is a lettered section with its own numbers, so this is section M, steps 67-74, beside L's 67-75.
**Watch out for:** (1) The committed 2025 packs predate `rosters` (v16), so the test grafts one on; a sample run on 2025 builds a fresh pack from the database and does carry rosters. (2) `parsePath` is deliberately strict (`games.0`, `games[0]margin`, `games[-1]` are all null), because a model that writes a near-miss path should be told so, not guessed at.

## Step 87 — bracket derivation: `playoffBracket()`
**Date:** 2026-11-14  **Status:** done
**Built:** `src/lib/playoff-bracket.ts`: `playoffBracket({ season, matchups, playoffTeams, regularSeasonWeeks })` returning the contract's `PlayoffBracket | null`, plus `bracketGameId()` and `thirdPlaceGameId()`. Seeds come from `completeWeeks()` rows for weeks 1..N; the shape from `bracketOrder()` / `byesFor()`; stored playoff rows only fill scores and advance winners. `src/lib/playoff-bracket.test.ts`, 29 tests: the committed 2025 season truncated to weeks 13, 14, 15, 16 and 17, agreement with `winners_bracket.json`, nine contradiction cases, season isolation, a half-recorded round, the tiebreak, four-team and two-team fields, and all six Sleeper seasons. Suite 951.
**Decisions:** (1) **Contradictions are found by consumption, not by a list of rules.** Stored championship-path and third-place rows are keyed by round, placement, manager and opponent; each derived game with two known sides looks up its own two rows; at the end any row nobody claimed returns null. Wrong opponents, a team that should not be playing, a round before its feeder and a final stored as placement 3 are all the same failure, so a new kind of bad row fails closed without a new check. (2) A game needs both its rows, mirrored, with a winner: half a game, two rows that disagree, or a tie returns null. (3) Seeding is wins, points for, then manager id ascending. The last step is determinism only and is documented as not a league rule; if the real tiebreak ever goes the other way the stored rows contradict the pairing and no bracket is drawn. (4) Ids are `r{round}-g{n}` top to bottom in bracket order and `r{last}-third`; side `a` is the upper slot. (5) `winnerOf` for an unknown side is the lowest and highest seed that can still arrive there: exact one round ahead (`[4,5]`), the range of a half two rounds ahead (`[1,5]`, `[2,6]`). The third-place game carries the same pairs meaning "loser of", read with `placement`. (6) `currentRound` counts the third-place game; `alive` is only the champion once the final is played; a third-place game is drawn only when both finalists come out of a game. (7) A playoff row inside the regular season, or past the last round, means the settings handed in do not describe the data, and returns null.
**Learned:** (1) **The derivation reproduces Sleeper's bracket for all six seasons on record, not only 2025.** Written against 2025 and then run untouched over 2020 to 2024: wins-then-points seeding and the fixed bracket give the same pairings, the same winner in every drawn game and the same champion in each (36 games). So the contradiction rule has never had to fire on real data, and that is now a test. (2) **2020 ran thirteen regular-season weeks** (`playoff_week_start` 14), with round one in week 14. Nothing may assume fourteen; the function takes `regularSeasonWeeks` and the test pins the 2020 value. (3) In 2025 the final's `winnerOf` pair happens to be the same before and after round one (`[1,5]` and `[2,6]`), because the 5 and the 6 both won. A test reading only 2025 cannot tell "range of the half" from "the two seeds in the semi"; the four-team case (`[1,4]`, `[2,3]`) is what pins the meaning. (4) The importer script runs `main()` on import, so its bracket tagging (which playoff-week games are kept, and `p: 1` stored as null) cannot be imported by a test. The test repeats those dozen lines on top of `pairWeek` and `playoffRound`; if the importer's tagging changes, this fixture will not follow it. (5) A fresh worktree fails `npx tsc --noEmit` on `src/app/layout.tsx` (`LayoutProps` not found) until `npx next typegen` has written `.next/types`; it is nothing to do with the change.
**Watch out for:** (1) `winnerOf` cannot say "loser of". On the third-place game a component must branch on `placement === 3`, or it prints "winner of 1 v 5" for a game between two losers. A `from: { gameId, outcome }` field on `BracketSide` was proposed to the orchestrator. (2) A re-seeded semi-final is invisible at week 15 and null at week 16: the bracket can be drawn one week and withdrawn the next. That is the locked decision working, but the page must handle null in a week after it showed a bracket. (3) A tied playoff game returns null for good, since nothing here knows the league's tiebreak. (4) Non-playoff rows at weeks beyond `regularSeasonWeeks` are ignored, not treated as a contradiction; none exist today. (5) Seed points are the sum of weekly rows, not Sleeper's stored season total. They agree for 2025; the importer's note says they differ slightly for eight rosters in 2020–21, which did not change any seed there.

## Step 88 — bracket odds: `teamRatings()` and `bracketOdds()`
**Date:** 2026-11-14  **Status:** done (wave 1, own worktree; not yet wired into the page)
**Built:** in `src/lib/playoff-odds.ts`, the rating maths (league mean, pooled `sigma`, shrunk rating, `ratingSd`) lifted into an exported `teamRatings(played): TeamRatings | null`, which `playoffOdds()` now calls; nothing else in the file changed. New `src/lib/playoff-bracket-odds.ts`: `bracketOdds(bracket, ratings, season): BracketOdds | null`, 10,000 simulations from the bracket's actual state with played games fixed, each game two draws around a per-simulation true rating, the model `playBracket()` uses. `src/lib/playoff-bracket-odds.test.ts`, 21 tests against a hand-built six-team bracket in the 2025 shape at five stages (round one pending, semis pending, one semi played, final pending, decided). Suite 943. `npm run local -- npm run odds:backtest`: 300 predictions over 2020–2025, Brier 0.159 model / 0.192 history / 0.240 baseline. `playoff-odds-baseline.json` unmodified and passing.
**Decisions:** (1) **`teamRatings` returns unrounded ratings, ascending manager id, plus `sigma` and `leagueMean`**, and null only for an empty `played`. `PlayoffOddsRow.rating` is the same figure to one decimal. (2) **Two generators, not one.** The championship path draws from one stream (a truth for every bracket team in seed order, then each unplayed game in round order, `a` before `b`); the third-place game draws its two scores from a second stream. Title odds are therefore identical whether the third-place game is pending, waiting or absent, and a test asserts equality. (3) **The pending third-place game gets a `games` entry** (third place pays) but never counts toward `gamesRemaining`, so it cannot keep `formatOdds()` hedging on title odds. (4) **Waiting sides are resolved from structure, not ids.** A side's `winnerOf` seeds are matched against the seeds that can still come out of each prior-round game; with `winnerOf` null it falls back to bracket position. (5) **Null, not a throw, for a bracket it cannot read** (a team with no rating, a played game with no winner, a side with no feeder, a last round that is not one game), on the same reasoning as "a contradiction draws no bracket". (6) Truths are drawn for all six teams even after four are out, so the stream does not depend on who is alive. (7) The generator and the normal draw are copied into the new file; nothing was exported from `playoff-odds.ts` beyond `teamRatings` and its two types.
**Learned:** (1) **The extraction is float-exact only because `teamRatings` rebuilds the per-team score lists by walking `played` in the same order** `playoffOdds()` did. The sums are `reduce` over those lists, so sorting or grouping the rows differently would change the last bits and fail the baseline's strict equality. The baseline passed on the first run. (2) **The contract leaves `winnerOf` undefined for the final and the third-place game.** In round two it is plainly `[4,5]`, but the final's side could be written `[1,4]`, `[4,5]` or `[1,5]`, and the third-place sides are losers. Matching on "seeds that can still emerge from that game" makes all of them work; a test reverses round one's array order to prove seeds beat position. (3) With equal ratings the model gives a bye team about 25% and a round-one team about 12.5%, which is the arithmetic of two wins against three; the test pins it. (4) `formatOdds()` uses its second argument only as "is it zero", so `gamesRemaining` is a flag in practice; it is still an honest count (5, 3, 1). (5) A fresh worktree fails `npx tsc --noEmit` on `LayoutProps` in `src/app/layout.tsx` until `npx next typegen` has written `.next/types`; it is not a code error.
**Watch out for:** (1) **Do not re-rate from playoff games.** Pass `teamRatings()` the `completeWeeks(...).complete` rows, which exclude playoff rows already; the same expression `getSeasonSoFar()` hands `playoffOdds()`. (2) The seed is season × 100 + `bracket.throughWeek`, so the odds move every Tuesday and never on reload; a bracket whose `throughWeek` does not advance with results will show stale-looking but stable numbers. (3) `title` drops any `alive` id that is not in `bracket.teams`, so a malformed `alive` shows as a sum below one rather than an error. (4) When the final is on record but `championManagerId` is not yet written, the result is null: no odds on a decided bracket, even with a third-place game notionally pending. (5) A playoff tie or forfeit leaves a played game with no winner, which is null here, consistent with step 87's contradiction rule. (6) Adding a draw to `teamRatings` moves every published odds figure; it takes no generator on purpose and a test checks its arity.
